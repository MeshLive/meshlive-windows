# Switches

The register of experimental, alternative and optional behaviour in MeshLive for Windows. Most switches are
environment variables read when the app starts; a few rows are Settings switches. Every experiment ships **off by
default** and labelled Experimental; the losing arm of an A/B comparison stays switchable instead of being deleted.

How to read the table:

- **Beta**: a guard that was promoted to on by default for the beta. `=0` selects the earlier behaviour (the control
  arm), kept for comparison.
- **Experimental**: off by default. Turn it on only for testing, and only with compatible peers where the row says so.
- **Alternative**: the earlier or other arm of a decided choice; the default is the measured or reviewed one.
- **Optional**: a user or diagnostic option that does not change the protocol.
- **Native unit-test binary only / Test hook / Test-only**: read only by the opt-in phone checks in the unit-test
  binary, by `--features test-hooks` builds, or by test tools. The release `meshlive.exe` never reads them.

Wire format and security rules are owned by [meshlive-android's protocol reference](https://github.com/MeshLive/meshlive-android/blob/main/docs/dev/protocol/README.md).
No switch here changes them unless its row says so. Build-time variables (`MESH_FXC`, `MESH_OPUS_LIB`,
`MESH_AOM_LIB`, `MESH_VPX_LIB`) are described in [building.md](building.md).

When you add, promote or retire a switch, update this table in the same change.
